## 1. v1 首轮发现的缺陷（AI 辅助审阅定位，非真人评分）

依据 `formal-v1` 与 `artifacts/submissions/initial-local/evidence/ai-formal-review.md`：

| 类别 | 证据示例（v1 原句） | 影响 |
|---|---|---|
| 商品名错字 | BD-103「青榄」、WAKE-103「青澜」（规范名「青岚」） | 事实错误 |
| 所选子集写成完整规格 | REC-103「青岚目前资料里只有50ml这一规格」（目录另有 100 mL） | 规格误述 |
| 预算与他方价格与报价混写 | PRICE-102 把客户 1400 元预算关联成 100 mL 报价 | 金额误读 |
| 内部规则话术进入正文 | 「我这边不做任何预约承诺」「不涉及试用装赠送」「库存和留香表现就不多说」 | 生硬、AI 腔 |
| 无需求铺开 | 生日祝福插入选香；价格异议未问渠道却主动展开渠道／真伪说明 | 打扰 |
| 转述写成已核实／已完成 | 「已按今天更正」；「我核实到的信息是…」 | 越权表述 |
| 三稿同质 | 多条仅是问候、次序或换词差异 | 选择价值低 |
| 结构失败 | AFTER-105 首轮 JSON 非法（1/50） | 无候选 |

## 2. 修改与前后对照（S1，版本 formal-v2）

| 修改 | 前（formal-v1） | 后（formal-v2） |
|---|---|---|
| 运行时写作规则包＋事实纪律 | 「之前您试过的青榄」 | 「之前您试过青岚，说喜欢但不着急」 |
| 规格表述约束 | 「青岚目前资料里只有50ml这一规格」 | 「这次能比较的是砚泊 30 mL…青岚这次列出的是 50 mL」（REC-103） |
| 预算与报价分开 | 「两款同款同规格分别是：青岚50毫升980元、100毫升1580元」（1400 元误关联告警） | 「您这次预算最多 1400，100 mL 确实会超，50 mL 在预算内」且程序零告警 |
| 内部规则转译或省略 | 「我这边不做任何预约承诺」 | 「我帮您登记意向，由门店与您确认」且只说一次；AFTER-002 不再把未提退换的反馈转入售后流程 |
| JSON 模板语言中立＋语言要求 | 语言组首轮 12 例英文组仅 6 例合规 | language-s5 首轮 22/24，2 例经关联技术重试补齐 |
| 生成后告警器三类误报 | formal-v2 首跑 9 条告警（历史裸数字、跨 SKU 配对、价格区间） | 修复后 50 例重放零告警（真实错误对照组仍告警） |

formal-v2 为 50/50 结构成功、150 条，不需要 v1 首轮的 AFTER-105 类技术重试；但内容质量以真人评价为准，本表只证明缺陷类型在抽样与审阅中未复现。

## 3. 已知剩余缺陷与限制

- **英文输出遵从非 100%**：deepseek-flash 在中文主导提示下，英文组四次全组运行首轮合规为 6~10/12，最终以「首轮＋关联技术重试」补全；提示工程仍可改进（如更低温度或双语场景指令），未实施。
- **告警器已知盲点**：「两个容量共用一个错误价」的写法不会告警（消除跨配误报的代价）；派生总价豁免在「合计＋目录价整数倍」语境下可能放过个别错误和值（错误总价对照组仍告警）。
- **approved.jsonl 仍为空**：12 条示例草稿（`.cache/s1-style-drafts.jsonl`）待人工审阅后才会进入生成。
- **真人评价未完成**：D 报告与截图待真实评价者完成 150 条后生成；英文自然度需具备相应语言能力的人评阅。
- **未实施**：S2 持久会话／SQLite、S3 Web 工作台、S5 企业微信／微信客服接入、自动草稿（不自动发送）。
- **历史缺件**：v1 阶段的 AI 对话步骤截图待用户从旧环境提供；无法取得则如实留缺。
