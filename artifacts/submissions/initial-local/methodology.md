# B. Methodology · 栖序 QIXU 本地初版

本材料描述本轮实际建立的数据、工具和评价口径。模型运行数量、真实评分与最终结论以同目录的 evaluation-report.md、versions.json 为准；以下方法说明不等于质量已通过。

## 拆解任务

顾问输入本次资料或使用合成客户档案，选择生日与节庆、产品推荐、购后关怀、沉睡唤醒、活动邀请、价格异议之一，获得三条各自完整的中文微信候选，再选择、编辑、复制或弃用。保存草稿不表示发送。界面与批量共用生成函数，六场景只改变场景要求和必要资料。

首版业务资料全部虚构：栖序 QIXU 为精品个人香水品牌；四款香水共六个 SKU，八个客户档案、两场活动以及一份品牌规则、一份服务政策。青岚 50/100 mL 为 980/1580 元，暮光 50/100 mL 为 1080/1680 元，雨白 50 mL 为 1180 元，砚泊 30 mL 为 780 元。金额币种均为 CNY。活动时间为 Asia/Shanghai 并带 +08:00 偏移。价格与政策是演示设定，不是现实品牌事实。

合成政策允许到店试闻，活动需登记并由门店确认；当前没有可引用折扣、赠品或价格匹配。售后需凭证和商品状态核查，不能直接承诺退换、赔付或时限。商品库存和个人留香全部未知；雨白的甜感也未知。香调是品牌描述，不能扩写成原料、配方或功效。客户长期偏好、本次需求、购买者与收礼人分别保留。

## 解释原理

应用采用 Python、Streamlit、Pydantic 和一家 DeepSeek API。Pydantic 检查输入与三条候选结构；httpx 执行一次模型请求，无自动重抽。实际模型名、参数和代码／提示／事实摘要随每次运行保存，密钥只从本地配置读取。正式结果不能由测试替身或人工示例补齐。

data.py 读取少量 JSON 事实；generation.py 组合通用规则、当前场景和原聊天，调用模型并校验；records.py 分开保存输入快照、原始返回、机器候选与顾问编辑；evaluation.py 执行批量、冻结和八列导出。生成路径没有读取 expectations.jsonl 的入口。明确金额和容量检查仅为可定位告警，不能判定人物理解、完整回应或语气是否合格。

稳定客户／商品／SKU／案例／候选 ID 与版本快照为后续数据库、微信渠道和调度保留边界。当前没有数据库同步、自动发送、员工权限或调度实现。没有引入检索、工作流平台、需求卡抽取或自动修复，也没有复制整个公开基准平台。

## 展示实验

测试集在观察正式输出前分为 20 个开发例、30 个保留例。每例有 1–3 个必须回应的要点及禁止行为，答案不写成唯一标准话术。数据由 AI 辅助起草，待真实评价者审阅；它不是人工评分，也不冒称真实客户样本。

本轮最终数据为 `cases-v1.1`。独立的 AI 复核发现两个保留例延续开发例的同一故事，以及一个购后例把旧关系和当前已购状态混在一起，现已在任何保留输出产生前改正。修改前后片段随包保存。多个案例仍共享合成客户与能力模式；字段和 family_id 检查不能证明语义上的完全独立，评分预期也尚未经真人验证。

先用六个开发诊断例检查链路：BD-001、REC-001、AFTER-002、WAKE-001、EVENT-001、PRICE-002。另有四个非正式边界例检查禁止联系、缺活动、缺祝福缘由、缺本次需求。边界例不替代正式五十例，也不计入模型质量分母。

开发例中的四个困难模式来自实际定向阅读 ABCD 固定版本 `6b8700ce67c6b37b062dd7a60abc76d7ef832a97`：train 对话 3592 的退换条件、10287 的渠道价格匹配、8252 的旧价冲突、7132 的失效优惠。完整压缩文件只下载到本地缓存用于选样；仓库仅保留必要短句、概括、来源映射与 MIT 声明。原姓名、联系方式、账号与原政策不进入正式数据。对应改写仅放开发集，同源家族没有跨到保留集。该工作不等于运行 ABCD 基准，也不能证明模型训练时没见过公开对话。[ABCD 数据说明](https://github.com/asappresearch/abcd/blob/6b8700ce67c6b37b062dd7a60abc76d7ef832a97/README.md)、[固定原始数据](https://github.com/asappresearch/abcd/blob/6b8700ce67c6b37b062dd7a60abc76d7ef832a97/data/abcd_v1.1.json.gz)、[许可证](https://github.com/asappresearch/abcd/blob/6b8700ce67c6b37b062dd7a60abc76d7ef832a97/LICENSE)。

数据检查实际验证了五十例唯一性、六场景配额、家族隔离、六诊断／十二复核抽样、每例评分要点、商品和客户引用、未知事实及四条公开来源映射。它只验证资料与程序合同，不证明模型输出质量。首次发现的聊天角色 `customer` 与模型合同 `client` 不一致已统一；修正后五十例解析及必要资料检查通过。

## 判断结果

每条候选单独评为“直接用”“小改可用”“实质改写”或“弃用”。小改只允许调整称呼、语序、标点、措辞和冗余；改错人物、金额、规格、政策、推荐方向或补遗漏顾虑，即使仅改一个字也属于实质改写。三条拼起来才完整不能算三条合格候选。组级另评是否至少有两种完整、合理且可说明差异的选择。

目标沿用既有报告：正式五十例共一百五十条真实候选并全数人工审阅；全部候选未观察到严重人物、金额／规格或虚构承诺错误；保留集至少 24/30 例有一条直接用或小改可用，至少 24/30 组有有用差异。生日节庆、推荐、购后、唤醒、邀请、价格异议的可用性底线分别为 3/5、4/6、3/5、3/5、2/3、4/6。这些是本项目建议试用门槛，非题目规定质量分数或行业标准。

主评人应先看机器原稿再看编辑稿，逐条记录判断、理由和严重错误。预先固定十二个复核例，每场景两例，由第二位真实评价者复核；保留双方最初判断和后续裁决。没有第二位评价者时明确说明；AI 辅助意见不得代替真人评分。未审阅的候选不算“没有错误”，只有实际审阅一百五十条才可写 0/150。

主要结果只报告保留三十例，开发二十例单列。失败和缺失不从分母删除；每次原始尝试保留，技术重试使用新运行关联原版本。看过保留输出后再改提示或参数，该集合后续只能称回归验证。共享虚构人物与困难模式意味着这些案例并非独立真实顾客；不能推出销售转化、真实客户满意度或零风险。未计准备、等待、选稿、修改总时长，不宣称省时。

Diptyque 私人邮件尚未用于本轮数据或提示；approved.jsonl 为空，没有把未经人工确认的风格示例称为已审核。任何后续优化应先记录实际缺陷，再只改变一个因素，展示同案例前后原始输出和改善／退步。当前数据合同修复属于工程集成修复，不是模型质量提升证据。

实际依赖版本与测试输出在 `evidence/offline-verification.json`。API 用法核验来源：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[JSON Output](https://api-docs.deepseek.com/guides/json_mode/)；表单和界面测试依据 [Streamlit 表单](https://docs.streamlit.io/develop/api-reference/execution-flow/st.form)、[AppTest](https://docs.streamlit.io/develop/api-reference/app-testing/st.testing.v1.apptest)。应用记录模型原始文本和用量。正式首轮49/50成功，唯一格式失败经一次关联技术重试补齐；首轮原表、最终八列表格和逐行来源均保留。AI辅助审阅不进入真人评分。当前没有真人内容评分或完整人机耗时对照。
