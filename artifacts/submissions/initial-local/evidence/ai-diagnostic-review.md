本文件记录 2026-11-06 两轮真实模型调用的程序结果及 AI 辅助内容观察。没有填写人工评分，不裁定“直接用／小改可用／实质改写／弃用”，也不作为独立人评。审阅者未调用模型、未修改输出、未读取本地密钥。两轮均为开发集六个诊断例，不是正式五十例评价，也未使用保留集输出。

## 解释原理

第一轮 AFTER-002 的 API 响应正常结束：`finish_reason=stop`，输出 426 token，低于 1800 的上限。失败原因是 JSON 语法不合法，每个候选对象的尾部多出 `,""`，例如 `{"text":"…",""}`。标准 JSON 解析器首次报错为 `Expecting ':' delimiter: line 1 column 227 (char 226)`。[实际原始返回](runs/diagnostic-v1/cases/AFTER-002/attempts.jsonl)

这不是网络超时或 token 截断。原始返回中虽能读到三段文字，程序仍正确记为 `technical_failure`、零条机器候选；没有删除多余字符后冒充成功，也没有覆盖第一次尝试。

第二轮只在系统提示追加以下一句，其他任务规则与场景模板保持不变：

> 每个候选对象必须且只能有 text 一个属性；text 字符串结束后用 } 闭合对象，对象之间用逗号分隔。不得添加空属性名、空字符串占位或尾随逗号；最终 JSON 须可直接解析。

这是对已观察到的格式失败增加约束，不是向提示加入测试答案。两轮完整提示均保存在各案例 `input.json` 的 `messages` 中，可直接比较。[第一轮输入](runs/diagnostic-v1/cases/AFTER-002/input.json)／[第二轮输入](runs/diagnostic-v2/cases/AFTER-002/input.json)

## 判断结果

以下是 AI 辅助发现的疑点及具体证据，不是人工评分，也不能据此生成可用率或“零严重错误”结论。

| 案例 | 可见改善或保留表现 | 退步、未解决问题与性质 |
|---|---|---|
| BD-001 | 两轮均按明确生日缘由祝福，第二轮更短。 | 两轮都在祝福中接续试香邀约；第二轮第三条仍说“我们不做催促”。这是自然度和沟通重心问题，是否需要删除由顾问判断。 |
| REC-001 | 两轮均区分妹妹与购买者，青岚 50 mL 980 元和砚泊 30 mL 780 元与资料相符；第二轮指出砚泊并非以柑橘为主。 | 第二轮第三条新增“我没有把两者混在一起”，把内部人物检查变成对客自证；也逐一解释未推荐商品，三条都很长。属于语气、冗余及候选差异不足的疑点，不能将格式成功算作内容改善。 |
| AFTER-002 | 格式失败被解决；第二轮第一条承接“实际闻着偏甜”，给出进一步了解体验的问题。 | 第二条重新询问是否拆封，输入已明确 `opened=true`。第三条说“这次青岚偏甜的感受，和您平时的偏好确实不太一样”，但档案长期偏好为“甜花香”，存在错误归因疑点。第二、三条又引入订单凭证及售后核查，而客户只在反馈体验；是否偏离任务需真人判断。这里不能与第一轮无有效候选构造完整内容评分差。 |
| WAKE-001 | 第二轮删去了第一轮第二条“不代表配方或留香表现”的内部边界说明，整体更短。 | 第二轮第三条仍主动说“具体库存我这边无法确认”，客户并未询问库存；这是多余的限制说明，尚未完全消除。 |
| EVENT-001 | 两轮日期、时间、地点、免费条件和登记后确认均与输入相符。第一轮第三条“告诉我人数和称呼即可”的未给定登记充分条件，在第二轮不再出现。 | 第二轮三条仍反复说明“目前还没预约／现在只是邀请”，消息略显流程说明；第二轮整体更长。须由真人判断三条是否形成有价值的不同选择。 |
| PRICE-002 | 两轮均核对同名不同容量，列出 50 mL 980 元、100 mL 1580 元，并说明没有价格匹配授权；第二轮更短。 | 三条主要仍是相同信息的顺序变化；第二条主动谈“真伪”虽未贬低渠道，但是否有必要由顾问判断。不能据规则无告警认定沟通质量达标。 |

第一轮与第二轮的明确事实自动检查均没有产生告警；这只表示当前局部规则未发现匹配项，不是人工审阅结论。尤其 AFTER-002 第三条涉及长期偏好的解释，属于规则检查之外的内容问题。

**冻结依据：** 可以保留这条 JSON 约束，把第二轮提示作为接下来正式评价的固定版本，因为它直接针对实际格式错误，且本轮结构结果没有退步；其余参数和事实已可追溯。冻结只是固定被评价对象，不能称内容已经通过验收。正式五十例应保留首轮结果，逐条真人评价，并重点检查上述人物归因、无关售后展开、内部规则外显和三候选差异问题。

这只是六个开发案例、每版本每例一次随机输出。结构改善可能受到抽样波动影响，不能证明新增一句能稳定消除格式错误，也不能推广为其他模型或真实客户的成功率。第二轮的自然语言变化并非本次格式约束的受控独立结果，不能给它归因或宣称全面质量提升。若正式保留输出被查看后继续调提示，应将该批案例称为回归验证。
