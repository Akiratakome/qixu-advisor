# E. Defects and next steps · 本地初版

## 拆解任务

本轮发现的问题来自真实 API 失败、程序检查、浏览器截图、AI 代码／数据复核及真实模型输出。工程／数据修正和提示格式实验分别报告，不把结构成功率等同于文案质量。

## 解释原理

保留原始失败和修改前证据，用同一路径检查改动是否解决已观察的问题。机器稿、人工编辑、评价修订及不同运行保持分离。结果所属版本记录在 `versions.json`；首轮失败不回写成成功。

## 展示实验

| 缺陷 | 实际修改前 | 实际修改后与验证 | 结论／限制 |
|---|---|---|---|
| Windows 阻止 uv 虚拟环境启动器 | `python.exe` 无法执行，报应用程序控制策略阻止 | 用可运行的项目 Python 调用标准 `venv` 建立启动器；Python、Pydantic、Streamlit 可运行 | 环境修复；未改变系统安全策略 |
| API 余额不足只显示状态码 | 真实 `smoke-20261106` 返回“HTTP 402；没有自动重试” | 错误提示明确余额不足；随后用户提供新凭据，关联 `smoke-recheck-20261106` 真实生成成功 | 原失败不覆盖；凭据变更带来的连通恢复不是提示质量改进 |
| 聊天角色合同不一致 | 新编数据使用 `customer`，模型接受 `client/user/advisor/assistant` | 数据统一为 `client`，五十例解析通过 | 数据集成修复，无模型内容结论 |
| 手机侧栏遮挡、生日表单包含无关字段 | [桌面原界面](screenshots/application/desktop-input.png)、[手机原界面](screenshots/application/mobile-input.png) | [桌面修改后](screenshots/application/desktop-input-after.png)、[手机修改后](screenshots/application/mobile-input-after.png)：顶部工作区、按场景显示字段，保留真实预填资料 | 实际截图检查；未做用户满意度测试 |
| 旧运行可被后来修改的案例／预期重新解释 | 隔离替身复现：更改源例场景后旧评分进入另一场景；修改预期未阻止评分 | 批量运行保存完整案例、清单、预期和量表快照，导出／评价使用对应版本 | 版本与导出回归见测试证据；替身评分不是人评 |
| 新提交失败仍可选用旧结果 | 新请求异常分支未清除上一客户的 `active_result` | 提交开始清理旧结果；同输入再次生成使用关联新运行，保留原结果 | 界面回归检查失败后不展示旧候选 |
| 家族 ID 检查漏过同一故事链 | 保留 AFTER-105、EVENT-101 延续开发 REC-001 的妹妹送礼背景 | 改为独立售后／活动代询任务，并同步预期；[修改前](evidence/data-before.json)、[修改后](evidence/data-after.json) | 在观察保留模型输出前完成；标签无交集不等于语义独立 |
| AFTER-103 旧档案与已购状态含糊 | 当前关系写“未购买”，本次输入又写已收到且开封 | 区分旧档案时间与本次已购事实，同步检查预期；前后见同上数据证据 | 输入澄清；不是证明模型能解决冲突 |
| 模型返回非法 JSON | `diagnostic-v1 / AFTER-002` 在三个对象末尾多出空属性，正常结束仍无法解析；六例结构5/6 | 仅追加JSON对象闭合约束，其他条件不变；`diagnostic-v2` 六例结构6/6；[真实对照](evidence/ai-diagnostic-review.md) | 改善1例、退步0例、另5例结构状态不变；没有真人质量评分，不能宣称整体质量改善 |
| 格式错误仍会复发 | 正式 `formal-v1 / AFTER-105` 再次非法JSON，首轮49/50成功 | 一次同输入／同配置技术重试 `formal-v1-technical-retry` 成功3条，单独关联；最终交付表150条，首轮表147条保留 | 诊断6/6不能证明稳定性；没有自动修复非法原文，也没有重抽成功稿 |
| 正式输出的内容疑点与规则误报 | AI辅助审阅发现商品名错字、未给定登记条件、任务回应遗漏、内部规则话术；局部金额检查把客户预算当报价触发4条告警 | 记录原句、资料依据及待真人判断项，见 [正式AI辅助审阅](evidence/ai-formal-review.md) | 本轮不再据保留输出改提示；后续调整只能作为回归验证，不降低门槛或掩盖失败 |

## 判断结果

已验证的改善是启动、错误解释、资料一致性、界面与记录可追溯性，以及六诊断例中格式失败数减少。模型前后原文完整保留；没有真人评分快照，不报告内容可用率提升、成本下降或时间节省。

仍需完成：

1. 真人审阅案例预期并逐条评价一百五十条真实候选，首轮和技术重试分开记录；第二位真人复核十二例，记录分歧和裁决。
2. 核验 AI 辅助报告中的问题，优先处理商品名、偏好归属、未给定条件和顾虑遗漏；谨慎修正金额检查的预算误报。
3. 根据真实缺陷选择一个改动做配对对照，保留改善、退步和无变化；不从多轮中挑好稿。
4. 补齐历史和本轮 AI 对话截图，以及真实评价截图。当前应用截图不能代替这两类证据。
5. 整理完整 A–E 包并由用户核对。当前未发送邮件、未发布网站或题目原文。

数据库、微信和调度属于后续扩展，当前没有把它们包装成已实现能力。
