# B. Methodology

版本：2026-11-09（formal-v16，奢侈品化测试集 cases-v2.1（案例方向修复＋用户批注落地））。描述实际实现与已执行验证；不声称尚未完成的人评结果。

## 1. 工具设计

- **产品形态**：React＋TypeScript＋Vite 顾问工作台（web/），由 FastAPI 单进程托管（静态＋SPA 回退）；Streamlit 保留为管理/人工评价入口。
- **主流程（单屏一体，无需滚动）**：粘贴/输入对话 → 自动理解这轮需求（防抖触发，场景/需求摘要/待确认问题可改）→ 点【生成三条候选】直接出三条 → 就地编辑、复制当前值、保存修改、选用/弃用。
- **冷启动**：生日/购后/唤醒/活动等无聊天记录的发起场景，基于客户数据库档案生成；无档案时按场景默认 prompt 生成（应用默认值记录 `cold_start_defaults_applied`，响应不暴露）。
- **两步生成**：分析（`analyze_conversation`：提示强制加载写作规则，摘要与问题措辞同样受去 AI 味约束）；生成（`generate`：一次调用输出三条各自完整的中文微信候选）。
- **去 AI 味（思考与输出都强制）**：写作规则包由分析与生成两条路径运行时加载；输出前强制门禁插件 de_ai.py（12 类 lint＋三类高置信确定性清洗），命中与清洗记录 `de_ai_report`，原始返回完整保留。
- **生日祝福真人样本**：样本句式取自公开祝福语合集（好作文网《会员生日祝福语》、第一范文网《vip顾客生日礼物祝福赠言》，登记于 data/references/sources.jsonl），仅作称呼与长度轻改；60–100 字通用祝愿、零商品、禁具体生活臆测；品牌自然融入正文一处（如「这份祝福栖序先替您记着」），不用落款署名（长寿面/年纪/健康承诺等）。
- **篇幅/语气生效**：简短 15–35 字删铺垫收尾、标准 60–120 字含得体承接；语气细化（natural 随聊/warm 多一句关怀/direct 结论先行）；temperature 按语气采样（0.7/0.9/0.3，显式设置优先），top_p 默认 0.9 可配（DeepSeek 无 top_k）。
- **持久会话与偏好**：SQLite 七表＋runtime_settings；乐观锁、生成幂等键、外部消息去重；草稿修订与复制留证（copied_text＋基准 revision）。
- **顾客自配 API**：侧栏模型配置（base_url/model/api_key/温度/top_p）；`POST /settings/model/test` 连通性自测（不回显密钥）；运行时配置优先于 .env。
- **外部客户数据库接入**：Supabase 示例（sources.py，只读、首次使用缓存本地快照），自建 CRM API 为第二个扩展示例；本地库/虚构目录优先。
- **事实与边界**：购买者／收礼人／本次需求／长期偏好分开；未知不补造；拒绝联系不生成；不发送微信；界面无开发者痕迹。
- **生成后事实告警器**：错字、规格、金额与报价不匹配（预算白名单）、未归属金额、推导金额（单位价/差价/合计语境窗口；第五轮覆盖每毫升差价与无连接词共享容量列表）。

## 2. 测试集设计（cases-v2.0，奢侈品化）

- **内容向奢侈品靠拢**：私人预览/限定品鉴邀请、高净值送礼（收礼人与购买者偏好分离）、香评术语（前调/后调/留香/sillage 仅作试香线索）、VIP 礼盒刻字售后、「贵但值得」式价格异议、SVIP 低频高价值唤醒。
- 50 例（开发 20＋保留 30，六场景配额 3/4/3/3/3/4 与 5/6/5/5/3/6）；每个场景覆盖五类：①正常任务资料完整 ②对象归属冲突 ③多轮纠正/预算或偏好变化 ④语言或语气变化 ⑤政策/缺资料/拒绝联系边界。50 个家族（qixu-v2-*）隔离，同故事不跨集。
- 设计依据：公开真人评价数据集的**结构与评价字段**（CoVal 的逐题 rubric 与 unacceptable 标记、DEP 的礼貌/上下文/重复维度、EmpatheticDialogues 的先承接再下一步、DialEval-1 的任务完成与满意度分离、Promptfoo 的案例合同与分层检查、Reddit 的继续交流信号）；不含任何外部原文、真人回复或外部政策。研究结论表见 data/cases 与交付包 E 引用的设计文档。
- 每例预期三键：must_respond／must_not／hard_fail_if（五类：need_unresolved/irrelevant_intent/fabricated_or_unauthorized/contact_boundary/unusable_structure）＋fact_checks；评分预期不进提示。
- 配套：rubric-v2.json（六维 0/1/2 量表＋AI 味判定边界＋两阶段评价协议）、research_seed_v1.jsonl（12 条研究种子：六场景×2，5 条英文、1 条拒绝联系）、unacceptable_examples.jsonl（8 条口径校准反例，非模型输出）。
- 补充组：6 条多轮序列、24 例语言组；独立运行、独立导出（沿用上一版数据，未重写）。

## 3. 评价方法（两阶段）

- **第一步硬失败筛查**：未解决需求/答非所问/事实或授权越界/联系边界错误/无法发送结构——命中即弃用并记录理由。
- **第二步可用性**：四档（直接用/小改可用/实质改写/弃用）＋六维锚点（任务完成/相关性/事实与授权/自然微信/情绪与关系/下一步，各 0/1/2）＋组级判断（至少两条独立可用、三稿非模板）。
- 真人评价：主评全部 150 条；第二位复核预抽 12 例（每场景 2 例），无则单人；分歧保留不用平均数掩盖一票否决。AI 审阅只定位问题，不填评分。
- 目标口径（新集首评，非回归）：保留集底线 24/30；每场景至少 3/5、4/6、3/5、3/5、2/3、4/6；每例至少两条不同合理完整选择；无观察到严重错误；硬失败率按类别与候选数报告，未评案例保留在分母。

## 4. 「好」与「不可接受」的定义

- 可用：对象、事实、回应与语气合适（直接用），或仅需称呼／语序／措辞级微调（小改可用）。
- 不可接受：严重事实错误；遗漏固定回应要点且无一条覆盖；三条实质同质；AI 味达到「必须重写主干」；为推销而偏离当前情形；编造价格/库存/优惠/预约/售后结果或把未知写成确定。
